# Model Study: 단계별 개선 효과 (progression_v1)

## 목표

규칙 엔진에 원래 쓰던 2차 분류기(1D CNN + URFD만으로 학습)를 붙였을 때와, 거기서 데이터 추가, 재학습(라벨과
학습-운영 입력 정렬), 모델/특징 변경, 임계값 조정을 하나씩 더했을 때 수치가 얼마나 바뀌는지를 **같은 held-out
클립, 같은 이벤트 단위 프로토콜**로 측정했습니다. 단계는 A 규칙만 -> B 1D CNN + URFD(원래 방식) -> C + 데이터 추가
-> D + 라벨/학습-운영 정렬 -> E + 모델/특징 변경 -> F + 임계값 조정이고, 모든 단계를 5개 fold에서 학습(4 fold)과
평가(1 fold)를 반복해 평균 ± 표준편차로 보고합니다. 분류기는 운영과 같이 **거부권(veto)만** 가지므로, 목표는
"규칙이 잡은 낙상은 지우지 않으면서 규칙의 오탐을 얼마나 지우는가"입니다.

모든 수치는 `dataset/_experiments/progression_v1/summary.json`(실행기 출력)과, 그 클립별 결과를 다시 집계한 값입니다.
두 번의 독립 감사(누수/프로토콜, 결과 재계산)에서 표의 수치는 클립별 결과로부터 오차 1e-16 이내로 다시 계산되었고,
학습/검증/평가 사이 누수는 발견되지 않았습니다. 다만 해석에 영향을 주는 주의점이 있어 [주의점](#주의점)에 정리했습니다.

## 요약

- **원래 방식(B)은 규칙만(A)보다 나빴습니다.** 규칙이 잡은 낙상 287개 중 평균 150.3개를 AI가 지워 recall이
  0.608 -> 0.291로 떨어졌고, balanced도 0.635 -> 0.434가 되었습니다 (5개 fold 모두 하락).
- **가장 큰 개선은 데이터였습니다.** 모델과 학습 방식을 그대로 두고 학습 데이터만 늘린 C는 B 대비 balanced
  +0.248 (5/5 fold 상승)이고, 규칙만(A) 대비로도 +0.047로 **5개 fold 모두에서 A보다 좋은 유일한 단계**입니다.
- **D(라벨/학습-운영 정렬)와 E(사건 구간 v2 특징 + 모델 변경)는 오탐을 크게 줄이는 대신 recall을 조금 잃습니다.**
  ADL 오탐률 0.174(C) -> 0.075(D) -> 0.050~0.065(E), recall 0.583(C) -> 0.517(D) -> 0.515~0.543(E).
  balanced로는 C와 차이가 fold 잡음(표준편차 약 0.05) 안이어서 **E가 C보다 낫다고 말할 수 없습니다.** E는
  "오탐 감소" 쪽으로 옮긴 선택지입니다 (E0 기준 ADL 오탐 77건 중 약 62건 제거, C는 약 35건).
- **E 안의 모델 차이(HistGradientBoosting 1.8만 노드, CNN-GAP 10만, TCN 4.3만)도 잡음 안**입니다. 작은 고전 ML이
  신경망과 같은 수준이므로, E의 개선은 모델 용량보다 "무엇을 보고 판정하는가"(사건 구간 창, v2 특징)에서 옵니다.
- **임계값 조정(F)은 개선을 만들지 못했습니다.** 스펙대로(검증 낙상 recall 1.0 유지) 고르면 임계값이 모든 run에서
  0이 되어 AI가 꺼진 것과 같아지고(A와 비트 단위로 동일), 검증 balanced 최대로 고른 임계값(0.00~0.19)은 검증에서는
  좋았지만 test에서는 E보다 balanced가 낮았습니다.
- **recall의 상한은 규칙 엔진입니다.** 낙상 클립의 60.8%(287/472)만 LEVEL1 판정까지 가고 AI는 거부권만 있으므로,
  어떤 분류기도 이 값을 넘지 못합니다. MCFD는 상한이 0.391입니다. 놓친 185개의 약 2/3는 누운 사람을 포즈 모델이
  검출하지 못한 경우입니다 ([FAILURE_ANALYSIS.md](FAILURE_ANALYSIS.md)).
- **(Day 5) E를 진입 이후 창들의 최대 p_fall로 판정하면(E\*) 세 모델 모두 좋아졌습니다.** 재학습 없이 balanced
  +0.023~+0.032 (15개 fold 비교 중 14개 상승), recall +0.040~+0.053 (15/15), ADL 오탐률 +0.030~+0.051.
  E0max는 recall 0.595, ADL 오탐률 0.113, balanced 0.711 ± 0.049로 이 연구의 최고값입니다. 다만 이득의 일부는
  알람을 더 많이 내는 쪽으로 동작점이 옮겨간 효과입니다. E의 임계값을 낮춰 같은 ADL 오탐률로 맞추면 E\*의 recall 이득은
  약 +0.7~+2.4%p로 줄고, 회복한 낙상 중 제때 알람은 절반이 안 됩니다 ([E\*](#e-진입-이후-최대-p_fall-day-5)).
- **(Day 6) 정상 데이터만으로 학습한 STG-NF는 AI 호출 AUC 0.84, 같은 오탐률 recall 0.569(seed 0.549~0.587)로
  지도학습 E0max(0.589)와 seed 편차 안에서 비슷했습니다(평균 2%p 낮음).** 낙상 라벨을 전혀 쓰지 않은 변형(GnfS)도
  같은 수준이고, 낙상 클립 약 90개(10%)만 라벨링한 지도학습도 비슷합니다(0.561~0.574). 이상 탐지는 MCFD에서 약합니다
  (창 AUC 0.58~0.63) ([G와 L](#g와-l-이상-탐지와-라벨-효율-day-6)).
- **(Day 7) 분류기 대신 앞단을 고친 효과가 가장 컸습니다.** 운영과 같은 재생 조건(대상 전환 리셋 포함)에서
  엔진의 짧은 미검출 유예(R1), 대상 전환 정책(R2), 회전 폴백을 더하자 규칙 상한이 0.542에서 0.822로 올랐습니다.
  E0max를 얹으면 탐지율 0.806, ADL 오탐률 0.150, balanced 0.827입니다(같은 분류기, R1만 0.732). 세 개선 모두
  5개 fold에서 같은 방향입니다 ([앞단 개선](#앞단-개선-엔진-처리와-회전-폴백-day-7)).

### 시간 기준 탐지 (알람이 낙상 자체에 대한 것인가)

위 표의 recall은 낙상 클립에서 LEVEL1이 **언제든** 한 번 나면 탐지로 셉니다. 그런데 A가 탐지한 낙상 287개 중 일부는
낙상 자체가 아닌 시점의 알람입니다. 이를 보기 위해 A를 다시 재생해 첫 LEVEL1을 낸 에피소드의 ABNORMAL 진입 시각과
LEVEL1 시각을 라벨 낙상 구간 [fall_start, fall_end]와 비교했습니다 (클립 시간 기준).

- **엄격 기준:** ABNORMAL 진입이 [fall_start - 2초, fall_end + 3초] 안이고 LEVEL1이 fall_start 이후
- **느슨한 기준:** ABNORMAL 진입 또는 LEVEL1 중 하나가 [fall_start - 2초, fall_end + 3초] 안

엄격 기준에서 A의 287개는 제때 242개 + 제때 아님 45개입니다. 제때 아님 45개 = LEVEL1이 fall_start보다 먼저 12개
(MCFD 10, le2i 2) + ABNORMAL 진입이 fall_start보다 2초 넘게 먼저 20개 (MCFD 15, le2i 5) + ABNORMAL 진입이 fall_end보다
3초 넘게 늦음 13개 (모두 MCFD). MCFD는 A 탐지 72개 중 38개가 여기에 속합니다. 느슨한 기준에서는 254 + 33입니다.

읽는 법:

- C가 지운 낙상은 거의 모두 제때 알람(10.7/11.7)인 반면, **E가 지운 낙상은 절반 이상이 제때 아닌 알람**입니다
  (E0 18/31, E1 19.7/34, E2 24/44.3). 그래서 시간 기준으로 보면 E와 C의 차이가 E 쪽으로 기웁니다.
- 하지만 이 기준은 결과를 본 뒤 정한 것이고, "제때 아님"에는 실제 낙상 도중 울린 알람도 들어 있습니다. 예:
  le2i/Office/video_6은 3.48초에 ABNORMAL에 들어가고 낙상은 11.55~14.07초, LEVEL1은 abnormal_timeout으로 13.48초에
  납니다. E는 3.48초의 오래된 진입 창을 보고 p 약 0으로 거부했고, 그 뒤 실제 낙상에 대한 새 ABNORMAL 진입은 없었습니다
  (C와 D는 같은 클립에 p 0.8~1.0). 이는 지표의 착시가 아니라 **E 설계의 실제 약점**입니다 (아래 후속 과제).
- 따라서 이 표는 "E가 더 낫다"는 근거가 아니라, clip 단위 recall이 낙관적이라는 점과 E 억제의 성격을 보여주는 보조
  지표로만 씁니다.
- (Day 5) 이 집계는 이제 실행기에 들어 있습니다: `replay.timing`이 클립별로 `timely_strict`/`timely_loose`/`untimely`를
  남기고, `summarize`가 제때 recall과 시간 기준 balanced를 냅니다. 위 표는 첫 낙상 구간만 봤습니다. 실행기는 낙상이
  두 번인 클립(MCFD 72개)의 모든 낙상 구간을 보므로, A는 엄격 246 (0.521), 느슨 259 (0.549), 시간 기준 balanced 0.590이고
  제때 아님은 41개(enter_early 20, level1_before_fall 13, enter_late 8)입니다. B~F 결과 파일은 시간 필드가 생기기 전에
  만들어져 위 표(첫 낙상 기준)가 그대로 기준입니다.

## E\*: 진입 이후 최대 p_fall (Day 5)

E는 ABNORMAL 진입 시점의 4초 창 하나만 보고 판정합니다. 진입이 실제 낙상보다 훨씬 이르면(앉기, 숙이기에서 먼저 진입)
오래된 창을 보고 실제 낙상을 지웁니다 (위 le2i/Office/video_6). E\*는 같은 E 모델을 재학습 없이 그대로 쓰고,
판정 시점에 창 고르는 방식만 바꿨습니다.

- **max (E0max/E1max/E2max):** 진입 창부터 판정 시점 - 4초까지 0.5초 간격으로 4초 창을 만들어(엔진의 원시 키포인트 버퍼)
  가장 큰 p_fall로 판정. 첫 창은 E의 진입 창과 같아서, E가 통과시킨 알람은 E\*도 항상 통과시킵니다 (호출 1,083개에서 확인)
- **last (참고):** 판정 시점 직전 4초 창 하나. 재생에서는 대부분 정지 꼬리(같은 프레임 반복)라 E가 학습한 적 없는 입력입니다

- max는 세 모델 모두에서 일관되게 recall을 되찾고(15/15 fold), E가 냈던 알람은 하나도 잃지 않습니다.
  대신 ADL 알람을 7~12개 더 통과시켜, "E는 오탐 감소 쪽, E\*는 그 중간"으로 C와 E 사이의 선택지가 됩니다.
- balanced 상승(+0.023~+0.032)은 일관되지만 크기는 fold 표준편차(약 0.05) 정도입니다.
- **같은 오탐률에서 비교:** E\*는 임계값 0.4를 그대로 두고 여러 창의 최댓값을 쓰므로 알람이 늘어나는 쪽으로 동작점이
  옮겨갑니다. E의 임계값을 낮춰 E\*와 같은 ADL 오탐률(0.113 / 0.096 / 0.090)로 맞추면 E의 recall은
  0.563 / 0.552 / 0.554이고 E\*는 0.595 / 0.577 / 0.569입니다. 즉 같은 오탐률에서 E\*의 recall 이득은 +3.2 / +2.5 / +1.5%p입니다.
  이 계산은 억제 후 승격을 무시해 E를 약 0.7~0.9%p 낮게 잡으므로, 실제 이득은 약 +0.7~+2.4%p입니다 (seed 평균, 첫 AI 호출의
  p_fall로 임계값을 훑은 근사).
  이득의 방향은 유지되지만 크기는 balanced 표의 차이보다 작습니다.
- 회복한 낙상 중 엄격 기준 제때 알람은 절반이 안 됩니다 (E0max 11.3/25). 일부는 같은 에피소드 안의 나중 창이 낙상을 본
  경우이고, 일부는 제때가 아닌 진입에서 난 알람을 되살린 것입니다. 시간 기준 balanced로 보면 E\*가 A보다
  +0.05~+0.07 높습니다.
- E1max에서 최댓값의 약 62%(690/1,112 호출)가 진입 창이 아닌 나중 창에서 나왔습니다 (호출당 창 약 16개).
- last는 모든 fold에서 E보다 나쁩니다. 판정 시점의 창은 누워서 정지한 구간이라 E가 학습한 낙상 동작이 없습니다.
  이는 Day 1~4에서 정리한 "CNN이 낙상 동작을 보지 못함" 문제를 다시 확인한 결과입니다.
- 런타임 연결 시(Day 8) E\* 방식은 판정 시점에 창 약 16개를 계산합니다. 사건당 한 번이라 부담은 작을 것으로 보지만,
  지연은 노트북에서 잽니다 (Jetson은 2026-10-18부터 쓸 수 없음).

## G와 L: 이상 탐지와 라벨 효율 (Day 6)

낙상은 정상 행동보다 드물고 라벨 비용이 큽니다. 두 가지를 같은 5-fold, 같은 판정 방식(E\*max: 진입 이후 4초 창들의
최댓값, veto 임계값 0.4)으로 쟀습니다.

- **G:** 정상 행동만으로 학습해 벗어나는 정도를 점수로 쓰면 어디까지 되는가
- **L:** 지도학습에 낙상 라벨이 얼마나 필요한가

### 방법

- **G (이상 탐지, `training/anomaly/`):** 양성 창 없이 정상 창으로만 학습합니다.
  - 정상 집합은 E 학습 창 중 y = 0인 창입니다. Figshare ADL 클립 창(클립 끝 기준: 약 1.9초 클립 + 마지막 자세 2초),
    ADL 슬라이딩 창, ADL에서 규칙이 진입한 창, 낙상 클립의 낙상 전 창이 들어갑니다. fold 0 기준 약 7,190개 중
    Figshare가 약 3,460개(48%)로 가장 많습니다.
  - Gmd: 손설계 특징(E0와 같음)의 Mahalanobis 거리 (LedoitWolf 공분산)
  - Gae: v2 창(92채널 x 60스텝)의 1D conv 오토인코더 재구성 오차 (관절 마스크로 가중, 7.2만 파라미터)
  - Gnf: STG-NF (Hirschorn & Avidan, ICCV 2023)를 직접 구현했습니다.
    - 입력: COCO-17 포즈 1.6초(24스텝) 세그먼트, 몸통 길이 단위, 세그먼트 평균 골반으로 중심화
    - 흐름: ActNorm, 2x2 가역 합성곱, ST-GCN 결합층을 K = 8번 쌓음 (5,008 파라미터)
    - 점수: 정상 likelihood의 음의 로그(NLL). 창 점수는 세그먼트 NLL의 최댓값
    - 논문과 다른 점은 `training/anomaly/stgnf.py` 머리말에 정리했습니다(관절 형식, 15Hz, 정규화, 결측 처리, 사전분포 등).
  - GnfS: Gnf와 같은 모델을 ADL 클립의 창만으로 학습·보정합니다. 낙상 전 창은 fall_start 라벨로 잘라 내는 것이라, GnfS만 낙상 라벨을 전혀 쓰지 않습니다.
    학습 창(fold 0 기준 약 6,170개)의 절반 이상(56%)이 Figshare 클립 창입니다.
  - GnfE0: 창마다 Gnf 보정 확률과 E0 확률의 평균 (E0는 낙상 라벨 100%로 학습)
  - 보정(사전 등록): 검증 정상 창 점수의 80% 분위를 확률 0.4에 맞춘 의사 p_fall.
    즉 검증 정상 창 80%보다 덜 이상하면 억제합니다. 80%는 E가 ADL 알람의 약 80%를 막는다는 점에서 정했고, test 결과로 바꾸지 않았습니다.
- **L (라벨 효율):** E0, E1을 학습 fold 낙상 클립의 10/25/50%만으로 학습합니다.
  - 표본: clip_id 단위 중첩 표본 (10% ⊂ 25% ⊂ 50%)
  - 뺀 낙상 클립은 양성 창과 낙상 전 음성 창을 모두 뺐습니다. ADL 클립 창은 모두 씁니다.
  - E0 학습 방식은 100%와 같게 맞췄습니다(early stopping 명시).
- **같은 오탐률 비교:** 변형마다 첫 AI 호출 p_fall의 억제 임계값을 test 결과로 골라 ADL 오탐률을 E0max(0.113)에 맞춘 뒤 recall을 비교했습니다.
  - 임계값을 test에서 고르므로 성능 추정이 아니라 모델 순위 비교용입니다.
  - 억제 후 승격 알람은 무시한 근사입니다.

### 읽는 법

- **정상 데이터만으로도 꽤 갑니다.** STG-NF는 양성 창 없이 AI 호출 AUC 0.84를 냈습니다.
  같은 오탐률에서 recall은 0.569(seed 0.549~0.587)로 지도학습 E0max(0.589)보다 평균 2%p 낮지만,
  가장 좋은 seed는 E0max와 거의 같아(0.587) seed 편차 안의 차이입니다.
  세 이상 탐지 중에서는 STG-NF가 가장 좋았습니다(Mahalanobis 0.537, 오토인코더 0.529).
- **낙상 라벨을 전혀 안 써도 같습니다.** GnfS는 낙상 전 창 없이 ADL 클립만으로 학습했는데도 Gnf와 차이가 없습니다(AUC 0.841 vs 0.839, 같은 오탐률 recall 0.572 vs 0.569).
  다만 보정 결과 ADL 오탐률이 0.161로 더 높아, 정해 둔 0.4 임계값에서는 오탐이 많습니다.
- **낙상 클립 약 90개(10%)만 라벨링해도 지도학습이 이상 탐지와 비슷합니다.**
  - 같은 오탐률 recall: E1p10 0.574, E0p10 0.561 (Gnf 0.569, seed 0.549~0.587)
  - 25% 이상은 0.577~0.583, 100%는 0.581~0.589로 조금 높습니다. 다만 차이(1~2%p, 낙상 5~10클립)가 Gnf의 seed
    편차(3.8%p) 안이라, 라벨 10% 이상에서는 지도학습과 이상 탐지를 구분하기 어렵습니다.
- **약점은 MCFD입니다.** 이상 탐지의 MCFD 창 AUC는 0.58~0.63(Mahalanobis 0.603, 오토인코더 0.584,
  STG-NF 0.611~0.627)으로 지도학습(0.94)과 크게 차이 납니다.
  - MCFD 정상 창이 적어서는 아닙니다. 학습 정상 창 중 MCFD 창은 평가 데이터셋 중 많은 편이고, 낙상 전 MCFD 창을
    더 학습한 Gnf도 ADL 클립만 쓴 GnfS와 거의 같습니다(0.627 vs 0.611).
  - fold별로 보면 MCFD ADL 클립 8개가 모두 test에 들어간 fold 2가 가장 높습니다(Gnf 0.755). 이 fold에서는
    학습에 MCFD ADL이 전혀 없었습니다. 나머지 fold는 MCFD test 음성이 낙상 클립의 낙상 직전 창뿐이고, 이때 0.54~0.67로 낮습니다.
  - 원인은 가설로만 둡니다. 낙상 직전 창에 낙상 직전 움직임(비틀거림, 앉기, 자세 변화)이 섞여 어려운 음성일 수 있고,
    높은 광각 원거리 영상이라 포즈 잡음이 클 수도 있습니다.
- **결합(GnfE0)은 가장 높지만 잡음 수준입니다.** balanced 0.715, 같은 오탐률 recall 0.595로 E0max보다 각각 +0.004, +0.006입니다.
- **모든 변형이 규칙 상한 0.608 아래에 몰려 있습니다.** 같은 오탐률 recall이 0.53~0.60이라 분류기를 바꿔 얻을 이득은 작습니다.
  다음 이득은 Day 5 결론대로 앞단(포즈 검출)에서 나와야 합니다.

  연결을 추가해 다시 학습한 것이 위 결과입니다. 수정 전 Gnf는 AI 호출 AUC 0.837, pooled balanced 0.697로 수정 후(0.839, 0.697)와 차이가 거의 없었습니다.
- **보정:** 검증 정상 창 단위로 보정하지만 판정은 여러 창의 최댓값이라, 실제 ADL 억제율은 80%보다 낮게 나옵니다(Gmd·Gae·GnfS의 높은 오탐률).
  임계값과 무관한 비교는 AI 호출 AUC와 같은 오탐률 recall로 보면 됩니다.
- **결측 창:** STG-NF는 관절이 절반 넘게 보이는 세그먼트가 없는 창에 점수를 내지 않습니다. 3개 seed 합계 AI 호출 1,108번 중 12번은 모든 창이 이 경우라 판정 없이 규칙 알람을 그대로 냈습니다(fail-open).

## 앞단 개선: 엔진 처리와 회전 폴백 (Day 7)

Day 5 실패 분석에서 놓친 낙상의 원인은 대부분 분류기 앞단이었습니다. 놓친 낙상 185개 중 포즈 검출 117개, 그중 40개는 검출이 잠깐 끊긴 것이 엔진 처리에 걸린 경우였습니다.
Day 7에서는 분류기는 그대로 두고 앞단 세 가지를 바꿔 같은 5-fold로 쟀습니다.

- **R1 (짧은 미검출 유예, `Level1Params.lost_grace_s` = 0.5):**
  - 검출이 0.5초보다 짧게 끊기면 워밍업과 진입 신호 누적을 유지합니다.
  - ABNORMAL이면 타임아웃 판정을 이어 갑니다.
- **R2 (대상 전환 정책 multi):** 사람 후보가 2명 이상일 때만 대상 전환으로 봅니다.
  - 운영 대상 선택은 직전 상자와 IoU 0.3 이상인 후보가 없으면 "다른 사람"으로 보고 엔진을 리셋합니다.
  - 빠르게 넘어지면 연속 프레임의 상자가 크게 움직여, 혼자 있어도 이 리셋이 일어났습니다.
- **회전 폴백 (`app/engine/rotate_fallback`, 운영 `ROTATE_FALLBACK`):** 원래 방향에서 아무도 못 찾았고 5초 안에 대상을 봤으면, 영상을 90/270도로 돌려 직전 대상 근처의 사람을 다시 찾습니다.

### 읽는 법

- **운영 조건 기준, 분류기는 그대로 두고 앞단만 고쳐 탐지 상한이 0.542에서 0.822로 올랐습니다.**
  - E0max 분류기를 얹으면 탐지율 0.806, ADL 오탐률 0.150, balanced 0.827입니다.
  - 같은 분류기로 앞단을 고치기 전(운영과 같은 조건, R1만)은 0.732였습니다.
- **각 개선은 서로 다른 원인을 고칩니다.**
  - R1: 짧은 검출 끊김에 엔진이 리셋되던 문제
  - R2: 빠른 낙상을 다른 사람으로 오판해 리셋하던 문제
  - 회전 폴백: 누운 사람 미검출
  - 그래서 효과가 거의 더해집니다.
- **회전 폴백은 오탐도 늘립니다.** ADL 오탐(E0max + R1 + R2)이 28.3건에서 36.0건으로 늘었고, 주로 URFD(9 → 14)와 caucafall(3 → 5)입니다.
  바닥에 눕거나 엎드리는 ADL에서 사람을 더 오래 잡게 되면서 정지 판정까지 가는 경우가 늘었습니다.
- **MCFD가 가장 크게 좋아졌습니다.** E0max + R1 기준 탐지 103 → 120/184로, 높은 광각 카메라의 누운 사람을 회전 폴백이 찾았습니다.
- **분류기 E0와 E1의 차이는 여기서도 작습니다**(balanced 0.827 vs 0.826).
- 운영 적용 여부(R1, R2, 회전 폴백의 기본값)는 Day 8에서 정합니다. 모두 기본값은 기존 동작입니다.
- **폐기한 방법:** 포즈 모델 파인튜닝 1차는 쓰지 않았습니다. 놓친 누운 사람 32%는 회복했지만, 원래 잡던 작은 사람 검출이 100%에서 62%로 떨어졌습니다([ROADMAP Day 7](ROADMAP.md)).

### 주의

- **R2의 근사:** 후보 수는 추출기가 원본 fps로 센 값이고, 운영은 처리 속도(약 15fps)마다 셉니다. 건너뛴 프레임의 전환은 다음 처리 프레임에 합쳐 근사했습니다.
- **분류기 입력 분포:** E 모델은 폴백이 없는 v1 키포인트로 학습했습니다. 폴백 프레임(회전 검출)은 관절 신뢰도와 분포가 조금 다를 수 있어, 새 키포인트로 재학습하면 결과가 달라질 수 있습니다.
- **정지 꼬리:** 재생 방식의 한계(마지막 프레임 20초 반복)는 그대로입니다. 폴백으로 마지막 프레임에서 사람을 잡는 경우가 늘면 꼬리 효과도 함께 커질 수 있습니다.

### 분할: 5-fold event-group 교차검증

- `sklearn.model_selection.StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=0)`, 층화 = (dataset, label),
  그룹 = fold_group (같은 사건의 여러 카메라/중복 영상이 한 그룹; MCFD는 사건 하나의 카메라 8개가 한 그룹,
  Figshare는 피험자 단위). 배정은 `dataset/_experiments/folds_v1.json`
- 단계마다 4개 fold로 학습하고 1개 fold로 평가, 5개 fold 모두 반복. test fold 크기는 135~153 클립
- 학습 fold 안에서 event_group의 15%를 층화로 떼어 검증셋으로 씀 (early stopping, 모델 선택, F 임계값). 표준화
  (E1/E2 입력)는 학습 창으로만 맞춤

### 운영과 같은 재생 (이벤트 단위 지표)

`training/experiments/replay.py`가 키포인트 클립을 Jetson이 보는 obs 흐름으로 바꿔 실제 `app.core.level1.Level1Engine`에
넣습니다.

1. 15Hz(`RUNTIME_HZ`) 격자에서 가장 가까운 원본 프레임으로 리샘플
2. obs는 `app/core/obs_schema.build_observation`과 같은 구조 (bbox 정규화, keypoints/keypoints_raw, quality_score =
   평균 conf, frame_shape)
3. 운영과 같은 EMA 스무딩 `app.engine.smoothing.ema_smooth_keypoints_inplace` (클립마다 상태 초기화)
4. **정지 꼬리 20초 (`FREEZE_TAIL_S`):** 공개 클립은 5~34초라 운영 규칙의 10초 정지 전에 끝납니다. 마지막 프레임을
   20초 반복해 "마지막 자세가 그대로 유지된다"고 가정합니다. 낙상과 ADL 클립에 똑같이 적용합니다
5. 규칙 파라미터는 `study_params`로 코드 기본값에 고정 (`abnormal_timeout_s=10`, `ghost_timeout_s=10`,
   `ai_suppress_pfall_th=0.4`, `ai_escalate_s=60`, `ai_escalate_requires_drop=True`; `tests/test_level1_golden.py`와
   같은 값)
6. 클립 결과: 낙상 클립 탐지 = LEVEL1 이벤트가 하나라도 있음 (사유 무관), ADL 클립 오탐 = LEVEL1이 하나라도 있음

검증기는 엔진에 주입되고, p_fall <= 임계값이면 LEVEL1을 거부(`ai_suppressed`)합니다. 운영 경로와 같이 검증기가 판단을
못 하면(None) 알람을 막지 않습니다 (fail-open).

## 단계별로 배운 것

### A -> B: 원래 방식은 운영에서 낙상을 지웠다 (도메인과 라벨 문제)

- AI 호출 시점 AUC가 0.640에 그쳤고, 낙상 클립의 첫 p_fall 중앙값은 0.183이었습니다 (ADL 0.001). 즉 운영에서 보는
  입력에 대해 낙상을 대부분 "낙상 아님"으로 봤습니다.
- 모든 데이터셋 test 창 AUC는 0.442 (영상 전체 라벨 기준)이지만 URFD test 창만 보면 0.922 (fold 평균 0.875~0.980,
  감사 재계산 값)입니다. 모델은 URFD 안에서는 구분하지만 다른 카메라, 사람, 방으로 일반화되지 않았습니다.
- 원인으로 볼 수 있는 것: 학습 데이터가 URFD 낙상 30 / ADL 40 클립 중 학습 fold 일부뿐이고, 영상 전체 라벨이라 낙상
  영상의 걷는 구간도 1로 학습했으며, 학습은 30fps 원본인데 운영 입력은 15Hz EMA이고 LEVEL1 시점에는 대부분 정지
  꼬리(멈춘 자세)입니다.

### B -> C: 데이터가 가장 큰 효과

- 모델, 특징, 학습 방식을 그대로 두고 데이터만 늘렸는데 balanced +0.248 (5/5 fold), 억제된 실제 낙상 150.3 -> 11.7,
  AI 호출 AUC 0.640 -> 0.827.
- C는 규칙만(A)보다도 5개 fold 모두 좋았고 (+0.010 ~ +0.108), 오탐률을 0.323 -> 0.174로 줄이면서 recall은 0.025만
  잃었습니다.

### C -> D: 학습-운영 정렬은 오탐을 줄이지만 recall을 내준다

- 학습 창을 운영과 같은 15Hz EMA로 만들고 라벨을 낙상 후 구간으로 바꾸자 ADL 오탐률은 5/5 fold에서 줄었고
  (평균 -0.098), recall도 5/5 fold에서 줄었습니다 (평균 -0.066). balanced는 -0.020 (2/5 fold)로 순이득은 없습니다.
- 창 AUC는 0.818 -> 0.972로 크게 올랐지만 라벨 정의가 바뀐 결과라 직접 비교할 수 없고, 실제 판정 지점의 AUC는
  0.827 -> 0.873으로 더 작게 올랐습니다. 또 D는 정지 꼬리에서 잡힌 `kp_seq`로도 학습해서, 이득의 일부는 이 재생 방식에
  맞춘 것일 수 있습니다 (주의점 참고).

### D -> E: "무엇을 보는가"를 바꾼 효과, 모델 종류는 차이가 작다

- 멈춘 자세 대신 ABNORMAL 진입 순간의 사건 구간을 v2 특징으로 보게 하자 AI 호출 AUC가 0.873 -> 0.905~0.918로 올랐고,
  D 대비 오탐률은 더 낮고(E0 -0.014, 0/5 fold 상승) recall은 비슷하거나 조금 높습니다 (E0 +0.026, 4/5 fold).
- 손으로 만든 창 통계에 HistGradientBoosting(E0)을 쓴 것이 CNN-GAP(E1), TCN(E2)과 같은 수준입니다
  (E1 - E0 -0.006, E2 - E0 -0.020, 모두 fold 잡음 안). 지금 데이터 규모에서는 모델 용량이 병목이 아닙니다.
  **E0/E1/E2 중 "가장 좋은 모델"을 이 test 수치로 고르지 않습니다.** 하나를 골라야 하면 검증셋 기준으로 고르거나
  셋을 함께 보고합니다.
- C 대비로는 오탐률 -0.112 (5/5 fold 하락), recall -0.040 (5/5 fold 하락), balanced +0.005 (3/5 fold)로, 같은 수준의
  balanced에서 오탐 쪽으로 옮긴 선택지입니다. E0는 규칙이 낸 ADL 오탐 77건 중 약 62건을 지웠습니다 (C는 약 35건).
- 약점: ABNORMAL에 낙상보다 일찍 들어간 뒤 abnormal_timeout으로 LEVEL1이 나는 클립에서 E는 오래된 진입 창을 보고
  거부합니다. 모든 E 모델과 seed가 공통으로 놓친 낙상이 13개 (MCFD 7, le2i 6) 있고, 대부분 이 유형입니다.

### E -> F: 임계값 조정은 효과가 없었다

- 스펙의 "검증 낙상 recall 1.0 유지" 규칙은 모든 run(15/15)에서 임계값 0을 냈습니다. 검증 낙상 중 p_fall이 거의 0인
  클립이 매 fold 최소 하나 있기 때문입니다 (검증 최솟값 0.0000~0.0243, margin 0.05를 빼면 0으로 잘림). 결과는 AI를 끈
  것과 같아 A와 클립 단위로 완전히 같습니다.
- 검증 balanced 최대 임계값(F*b, 0.00~0.19)은 검증에서 0.689~0.710으로 0.4일 때(0.645~0.655, 감사 재계산)보다
  좋았지만, test에서는 E보다 낮거나 비슷했습니다 (F0b - E0 -0.027, 2/5 fold). 검증셋이 fold당 평가 클립 86~87개
  (낙상 58~59 / ADL 28~29)로 작아서 고른 값이 test로 옮겨가지 않았습니다.
- 0.4가 test에서 더 나아 보이는 것은 test 관찰일 뿐이며, 0.4는 운영 기본값을 바꾸지 않은 것입니다.

### 전체

- 원래 방식(B) 대비 개선: balanced 0.434 -> 약 0.68 (C, E0), recall 0.291 -> 0.54~0.58, 억제된 실제 낙상 150.3 ->
  11.7~31.0.
- 규칙만(A) 대비: 오탐률 0.323 -> 0.061 (E0) / 0.174 (C), recall 0.608 -> 0.543 (E0) / 0.583 (C), balanced 약 +0.05.
- 남은 가장 큰 손실은 규칙 단계입니다. 낙상 472개 중 185개(39%)는 LEVEL1 판정까지 가지 못하므로 분류기로는 되살릴 수
  없습니다 (MCFD 112/184).

## 주의점

결과를 무효로 만드는 문제는 감사에서 발견되지 않았습니다. 아래는 수치를 해석할 때 함께 말해야 하는 한계입니다.

1. **연출 낙상, 짧은 클립.** 공개 데이터는 배우가 연출한 낙상이고 클립은 5~34초입니다. 실제 설치 환경(카메라 높이,
   조명, 가림, 노인의 느린 낙상)과 다릅니다.
2. **정지 꼬리 가정.** 클립이 10초 정지 전에 끝나서 마지막 프레임을 20초 반복했습니다. 그 결과 v1 검증기(B, C, D)는
   거의 항상 멈춘 프레임을 판정합니다. LEVEL1은 낙상 알람 287개 중 219개, ADL 알람 77개 중 65개에서 꼬리 안에서 나고,
   낙상 211개(74%), ADL 60개(78%)는 꼬리에 2초 넘게 들어간 뒤라 30프레임 `kp_seq` 전체가 같은 프레임 반복입니다 (EMA
   수렴만 다름). 실제 10초 정지는 키포인트가 흔들리므로, D가 이런 입력으로 학습한 이득의 일부는 재생 방식에 맞춘
   것입니다. B/C/D 비교는 이 점을 감안해야 합니다.
3. **ADL이 적음.** ADL은 240 클립(합계 수십 분)이라 시간당 오탐 수치를 내지 않았습니다. 데이터셋별 오탐률의 0은 작은
   표본의 0입니다. MCFD ADL 8개는 모두 fold 2에 있어 MCFD 오탐률은 한 fold의 값이고, 검증셋에는 MCFD ADL이 없습니다.
4. **규칙 상한.** AI는 거부권만 있어 recall은 0.608(287/472)을 넘을 수 없습니다. AI 호출 AUC는 p_fall이 기록된
   낙상 284 / ADL 77 클립에서 계산했습니다.
5. **clip 단위 recall은 낙관적.** 알람 시점을 보지 않으므로 A의 287개 중 45개(엄격 기준, MCFD 38개)는 낙상 자체에 대한
   알람이 아닙니다. 위 [시간 기준 탐지](#시간-기준-탐지-알람이-낙상-자체에-대한-것인가) 참고.
6. **피험자와 장소가 fold 사이에 겹침.** 스펙대로 event_group으로 묶었기 때문에, test 클립의 피험자가 학습 fold에도
   나옵니다: le2i 187/190, caucafall 100/100, gmdcsa24 160/160, mcfd 192/192 (피험자 id 하나), urfd 70/70 (피험자 정보
   없음). 처음 보는 사람과 방에 대한 절대 수치는 낙관적이고, 단계 간 비교에는 영향이 같습니다.
7. **fold 잡음.** fold 표준편차가 0.03~0.07이고 seed 간 pooled balanced 차이도 최대 0.036 (B)입니다. 5개 fold 모두에서
   방향이 같은 비교는 B < A, C > B, C > A와 recall/오탐률의 단방향 이동뿐입니다. C, D, E0, E1, E2의 balanced 순위는
   잡음 안입니다.
8. **창 AUC는 단계 간 비교 불가.** 단계마다 창 생성기와 라벨 정의가 다릅니다. B의 0.442는 모든 데이터셋에 영상 전체
   라벨을 쓴 값(URFD만 0.922)이고, D/E의 0.97~0.98은 라벨로 잘라 만든 창의 값입니다. 실제 판정 지점의 AUC(AI 호출 AUC,
   0.873~0.918)가 운영에 더 가깝습니다.
9. **B 재현의 차이.** 학습 방식, 창, 정규화, veto 규칙(원래 엔진은 label 0이고 conf >= 0.6이면 억제 = p_fall <= 0.4)은
   9e40e48과 같지만 다음이 다릅니다.
   - 포즈 입력: 지금은 URFD mp4의 320x240 RGB 절반을 YOLOv8s-pose conf 0.5와 IoU 대상 선택으로 추출. 원래는 URFD PNG
     프레임에 ultralytics 기본 conf(0.25)와 첫 번째 검출
   - 검증 창 step 5 (원래 10), 검증 분할은 학습 fold 안 URFD event_group의 15% (URFD의 약 68%로 학습; 원래는 범주별
     80/20, seed 42)
   - B는 `fall_model_best.pth`의 학습 방식을 재현한 것이고, 운영에 배포됐던 `fall_model_active_best.pth`와 같다는
     보장은 없습니다
10. **모델 선택이 불안정.** B의 최고 검증 accuracy epoch는 seed/fold에 따라 2~50 (검증 창 159~264개), C는 15 run 중 3번
    epoch 1을 골랐고 C fold 2의 창 AUC는 0.62~0.66 (다른 fold 0.83~0.89)입니다. 원래 방식을 그대로 쓴 결과입니다.
11. **E의 오래된 진입 창.** 위에서 설명한 대로 ABNORMAL 진입이 낙상보다 이르면 E는 진입 창만 보고 거부합니다. E가 지운
    낙상의 절반 이상이 이 유형입니다.
12. **임계값 0의 경계.** 판정이 `p_fall <= th`라 th = 0일 때 softmax가 정확히 0.0으로 내려가면 여전히 거부됩니다. 이번
    실행에서는 일어나지 않았습니다 (F0/F1/F2가 A와 완전히 같음).
13. **중복 클립.** le2i Home_01 video_2 = video_3, Home_01 video_20 = video_21, Home_02 video_49 = video_50은 키포인트가
    같습니다. 같은 event_group과 fold라 누수는 아니지만 평가에서 두 번 셉니다 (낙상 2쌍, ADL 1쌍).
14. **학습 내부 사항 (누수 아님).** E0 HistGradientBoosting은 sklearn 내부 early stopping으로 학습 창의 무작위 10%를
    떼어 씁니다 (같은 클립의 증강 창이 양쪽에 있을 수 있음). 학습 데이터 안의 일이라 검증/평가에 영향은 없습니다.
15. **후속 실험 시 누수 위험.** `windows.py`에 적힌 "ABNORMAL 진입이 fall_start보다 약 1.0초 늦다"는 값은 test fold를
    포함한 모든 클립에서 잰 것입니다. 이번 실행은 `onset_offset_s=0.0`이라 해당 없지만, 1.0으로 바꾼 변형을 돌린다면
    fold마다 학습 클립으로 다시 재거나 약한 누수로 명시해야 합니다.

## 재현 방법

준비: manifest와 키포인트 ([DATASETS.md](DATASETS.md)), numpy/torch(CUDA)/sklearn이 있는 Python. 저장소 루트에서:

```bash
python -m training.experiments.run_progression --stages A,B,C,D,E,F --folds 0-4 --seeds 3 --jobs 5
python -m training.experiments.run_progression --stages Es --folds 0-4 --seeds 3 --jobs 5   # E*: 저장된 E 모델 재사용
python -m training.experiments.run_progression --stages L,G --folds 0-4 --seeds 3 --jobs 5  # 라벨 효율, 이상 탐지
python -m training.experiments.run_progression --summarize-only   # summary.json / summary.md만 다시 생성
```

- 출력: `dataset/_experiments/progression_v1/` (`fold{k}/{변형}.json`에 클립별 결과, `fold{k}/models/`에 E 모델,
  `logs/`, `summary.json`, `summary.md`). fold 배정은 `dataset/_experiments/folds_v1.json` (없으면 생성)
- 이미 있는 결과를 건너뛰려면 `--skip-existing`, 점검용으로 epoch 상한을 줄이려면 `--epochs N`
- 걸린 시간 (RTX 4050 노트북, 5개 fold 합계 초): A 34, B 359, C 9,255, D 1,267, E0 420, E1 618, E2 927, F 변형 각 약 190.
  `--jobs 5`로 fold를 병렬로 돌리면 실제 시간은 이보다 짧습니다. E\*(Es)는 재학습이 없어 `--jobs 5`로 약 3.5분,
  L은 약 9.5분, G는 약 62분 (STG-NF 학습이 fold·seed당 약 8~10분)
- 코드: `training/experiments/` (`replay.py` 재생과 지표, `folds.py` 분할, `windows.py` 창, `models.py`, `trainer.py`,
  `verifiers.py`, `run_progression.py`), 이상 탐지는 `training/anomaly/` (`stgnf.py`, `autoencoder.py`, `mahalanobis.py`,
  `segments.py`, `calibrate.py`)
