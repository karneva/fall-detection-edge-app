# 실패 원인 분석 (failure_v1)

규칙 엔진만으로 재생한 단계 A에서 놓친 낙상, 제때가 아닌 탐지, ADL 오탐을 원인별로 셌습니다.
다음 작업(Day 7 포즈 모델 개선, 규칙 개선, 장면 분할)을 무엇부터 할지 정하려는 분석입니다.
판단 기준은 분석 전에 [ROADMAP](ROADMAP.md)에 적어 두었고(d0fd968), 결과를 본 뒤 고친 부분은 [결정](#결정)에 따로 밝혔습니다.

## 요약

- **놓친 낙상 185개 중 약 2/3(117개)가 포즈 검출 문제입니다.** 사람이 화면에 보이는데 운영 설정(conf 0.5)의
  YOLOv8s-pose가 그 사람을 검출하지 못합니다.
  - 자동 분류: 포즈 117개(63%), 규칙 46개(25%), 라벨 12개(6%), 재생 방식 10개(5%)
  - 포즈 117개 중 77개는 낙상 구간 대부분에서 검출이 없음.
    40개는 검출이 간헐적이라 엔진의 미검출 처리(한 프레임만 놓쳐도 워밍업이 0부터, 미검출 중에는 판정 정지)에 걸림
  - 무작위 30개를 프레임으로 확인: 보이는데 미검출 21개(70%), 포즈는 정상인데 규칙 미발동 6개(20%), 일어남 2개, 가림 1개
- **임계값만의 문제는 아닙니다.** 미검출 프레임 1,396장을 같은 모델로 conf를 낮춰 다시 돌렸습니다.
  - conf 0.25에서는 33%, conf 0.1에서는 54%가 직전 위치 근처에서 검출됩니다(파일럿).
  - 임계값을 낮추면 일부를 되찾지만, 나머지는 모델 개선이 필요합니다.
- **누우면 검출이 끊깁니다.**
  - 놓친 낙상의 사람 검출률은 낙상 전 3초 0.85에서 낙상 뒤 0.59로 떨어지고, 제때 탐지한 낙상은 0.97에서 0.94입니다.
  - MCFD 외 데이터셋은 놓친 낙상도 낙상 전에는 0.93~1.00으로 잘 잡힙니다.
  - MCFD는 낙상 전부터 0.78로 낮습니다. 놓친 112개 중 21개는 낙상 전에도 검출률 50% 미만이라,
    누운 자세뿐 아니라 높은 광각 카메라의 원거리·작은 사람 문제도 섞여 있습니다.
- **MCFD가 놓친 낙상의 61%(112/185)입니다.** 높은 곳에 단 광각 카메라 8대가 매트리스 위 낙상을 찍은 데이터입니다.
- **규칙 원인 중 직접 확인한 6개:**
  - 3개는 카메라 시선 방향으로 누운 경우입니다. 정규화 bbox 세로/가로가 약 1.75~4.1로 남아 "누움" 조건(1.6 미만)을 넘지 못합니다.
  - 나머지 3개: 대각선으로 누워 bbox가 정사각형에 가까움 1, 평평해진 직후 클립이 끝남 1, 소파에 앉듯이 넘어짐 1
- **ADL 오탐 77개 중 34개는 앉은 채로 끝납니다.** 의자 21, 소파 6, 침대 4, 바닥 3.
  침대·소파에 누운 경우는 12개(16%)이고, 65개는 정지 꼬리(마지막 프레임 20초 반복) 안에서 알람이 났습니다.
- **결정:**
  - Day 7 포즈 모델 개선(P)을 진행하고, 그 전에 conf 임계값을 낮춘 기준선을 먼저 잽니다.
  - 규칙은 미검출 프레임 처리만 좁게 고치는 항목(R1)을 따로 측정합니다.
  - 넓은 규칙 개선과 장면 분할(S)은 보류합니다.

## 방법

- **대상:** 평가 클립 712개(낙상 472, ADL 240). 단계 A(규칙만), progression과 같은 재생(15Hz, EMA, 정지 꼬리 20초)
- **도구:** `training/experiments/failure_analysis.py`
  - 재생하면서 프레임마다 엔진 상태를 기록합니다.
  - 기록 항목은 사람 검출 여부, 워밍업 카운터, 진입 신호 4종(급하강·자세·어깨 하강·높이 감소), 누적 타이머, 붕괴 확정입니다.
  - 낙상이 여러 번인 클립(MCFD 72개)의 놓친 낙상은 첫 낙상 기준으로 봅니다.
  - 제때 판정(`replay.timing`)은 모든 낙상 구간을 봅니다.
- **놓친 낙상 원인 판정.** 관련 에피소드는 진입이 [fall_start - 2초, fall_end + 3초] 안이거나, 그 전에 진입해 낙상 시작까지 이어진 것입니다.
  - 관련 에피소드가 없으면 낙상 구간 [fall_start, fall_end + 2초]에서 아래 순서로 판정합니다.
    1. 프레임 절반 이상이 미검출 또는 품질 0.15 미만이면 `pose_lost_during_fall`
    2. 보이는 프레임 절반 이상이 워밍업(12프레임) 미달이면 `detection_flicker`
    3. 부분 신체 판정이 절반 이상이면 `partial_body`
    4. 진입 신호 2개 이상이 잠깐 있었지만 0.35초 연속을 못 채우면 `signals_too_brief`
    5. 클립 끝 1초의 bbox 세로/가로가 1.6 이상이면 `lying_bbox_not_flat`
    6. 그 밖은 `weak_motion_signals`
  - 관련 에피소드가 회복으로 해제된 경우:
    - 해제 무렵 라벨이 일어남(stand_up/standing/walk)이면 `got_up_per_label`
    - 해제가 라벨 구간이 끝난 뒤면 `unlabeled_exit`
    - 그 밖은 `false_recovery`
  - 해제 없이 끝났는데 마지막 실제 프레임이 미검출인 경우:
    - 1초 이상 이어진 미검출이면 `lost_after_fall`
    - 마지막 프레임 하나 수준이면 `tail_last_frame_lost`(재생 방식: 정지 꼬리가 그 미검출 프레임을 20초 반복)
  - 해제 없이 끝났는데 붕괴 확정이 안 됐으면 `timeout_unconfirmed`
- **임계값 파일럿:** 포즈 묶음 117개 클립에서 저장된 키포인트로는 미검출이거나 품질이 미달인 프레임을 클립당 최대 12장 골랐습니다(1,396장).
  - 같은 yolov8s-pose를 conf 0.05로 다시 돌렸습니다.
  - 직전 정상 검출 bbox 근처에서 관절 평균 신뢰도 0.15 이상인 사람만 셌습니다.
  - 오탐 증가는 재지 않았습니다(Day 7에서 재추출로 측정).
- **직접 확인:** 놓친 낙상 무작위 30개(seed 0)와 ADL 오탐 77개 전부를 확인했습니다.
  - 그림: 영상 프레임 6장에 키포인트와 bbox를 겹쳤습니다(`render_sheet`).
  - 태깅: Claude(비전 모델)가 그림을 보고 태그를 달았습니다. 사람이 다시 확인하지 않았습니다.
  - 태그 파일: [eval/annotations/failure_v1_manual_tags.json](../eval/annotations/failure_v1_manual_tags.json)

## 결정

분석 전 기준(d0fd968):

1. 포즈 원인이 약 1/3 이상이면 Day 7은 포즈 모델 개선(P)
2. 규칙 판정이 주원인이면 Day 7은 규칙 개선(R)
3. 침대·소파 누움 오탐이 많으면 Day 9에 장면 분할(S)

결과 커밋(55d1b01)에서 이 기준을 "P는 결과와 무관하게 진행, R은 규칙 원인 약 1/3 이상이면 추가"로 바꿨습니다.
R의 1/3 기준은 결과를 본 뒤에 생겼으므로 사전 기준이 아닙니다. 아래 표는 두 기준을 모두 적용합니다.

| 판단 | 결과 | 결정 |
| --- | --- | --- |
| P (원래 기준: 포즈 약 1/3 이상) | 자동 63%, 직접 확인 70% (52~83%) | 진행. 목표 장면: 누운 자세, 높은 광각 원거리(MCFD), 어두운 실내(le2i Home) |
| P 이전 기준선 | 파일럿: conf 0.25에서 미검출 프레임의 33% 회복 | Day 7에서 conf 임계값만 낮춘 기준선을 먼저 재고, 파인튜닝은 이것을 넘어야 함 |
| R (원래 기준: 규칙이 주원인) | 규칙 자동 25%, 직접 확인 20% (9.5~37%): 주원인 아님 | 넓은 규칙 개선은 하지 않음 |
| R (엔진의 미검출 처리를 규칙으로 보면) | 자동 (46 + 40) / 185 = 46% | 미검출 프레임 처리만 고치는 좁은 항목 R1을 Day 7에 따로 측정 (한 프레임 미검출에 워밍업 리셋 안 함, ABNORMAL 중 짧은 미검출에도 시간 누적) |
| S (침대·소파 누움 오탐) | 12/77 (16%) | 보류. 가장 큰 유형은 앉기(34)이고, 사건 구간 분류기(E)가 이미 ADL 오탐률을 0.32에서 0.05~0.065로 줄임 |
| Day 7을 Day 6보다 먼저? | 앞단이 바뀌면 Day 6 이상 탐지를 다시 재야 함 | Day 6은 예정대로, Day 7 뒤 새 키포인트로 G 재측정 |

포즈 개선의 기대 상한:

- 포즈 묶음 117개가 모두 회복되면 규칙 상한은 0.608에서 최대 약 0.86((287 + 117) / 472)까지 오릅니다.
- 회복된 프레임도 규칙 조건(진입 신호, 정지)을 넘어야 하므로, 실제로는 이보다 낮습니다.

## 한계

- **임계값과 창:** 원인 판정의 비율 기준(0.5)과 창 길이는 처음 정한 값입니다.
  다만 리뷰에서 찾은 버그(낙상 뒤 한참 지난 에피소드 선택, 일어남 판정과 해제 시각 불일치, 정지 꼬리 미검출, 다중 낙상)를 고친 뒤 다시 셌습니다.
- **직접 확인 표본:** 30개라 비율의 신뢰구간이 넓습니다(규칙 20%의 구간 상한 37%).
- **태깅 주체:** 직접 확인 태그는 Claude가 프레임 6장을 보고 달았습니다. 자동 원인을 보고 달았으며 사람이 다시 확인하지 않았습니다.
- **해상도:** 규칙 원인 비율은 4:3 공개 데이터 재생 기준입니다.
  배포 해상도(1920x1080)에서는 bbox 비율 임계값 1.6이 픽셀 0.90에 해당해 "누움" 조건을 더 통과하기 어려우므로([DATA_CARD 6절](DATA_CARD.md)), 배포에서는 규칙 원인이 더 클 수 있습니다.
- **정지 꼬리:** ADL 오탐 대부분과 일부 탐지는 정지 꼬리 가정에 의존합니다.
  마지막 실제 프레임이 미검출이면 꼬리 전체가 미검출이 되는 문제(`tail_last_frame_lost` 10개)는 progression 결과에도 같이 있습니다.
- **대상 전환:** 클립 파일에 프레임별 대상 전환 기록이 없어 재생에서 전환 후 1초 유예가 빠져 있습니다(MCFD 132개 클립).
  추출기에 기록을 추가했으므로 재추출 후 반영됩니다.
